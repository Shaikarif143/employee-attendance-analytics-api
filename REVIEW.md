# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Unconditionally returned `{"status": "ok"}` without checking if MongoDB is alive. | Stop MongoDB process; `/health` still returned 200 instead of 503. | Pinned ping check `client.admin.command("ping")` inside a try-except block, raising HTTP 503 if unreachable. |
| 2 | `compute_late_minutes` (lines 33-37) | Replaced time directly on UTC datetime without converting to IST (+05:30); ignored overnight shift rules; failed to floor minutes. | A punch-in at 04:00 UTC (09:30 IST) resulted in shift start being set to 09:30 UTC, showing an erroneous 330 minutes late. | Converted UTC instant to IST, constructed shift start datetime using the correct attendance date, and computed floored elapsed minutes when strictly greater than the 10-minute grace period. |
| 3 | `compute_work_hours` (lines 40-41) | Used Python's built-in `round()`, which applies Banker's Rounding (round-half-to-even) instead of arithmetic Round-Half-Up required by rule R4. | An interval of 2.005 hours rounded down to 2.00 instead of rounding up to 2.01. | Implemented `Decimal.quantize(ROUND_HALF_UP)` on total elapsed seconds divided by 3600. |
| 4 | `compute_overtime` (lines 44-47) | Assumed shift end occurs on `date_str` (failing for overnight shifts), and omitted the 30-minute threshold rule (R3). | An employee punching out 15 minutes after shift end received 15 minutes overtime instead of 0. Overnight shifts showed ~24 hours overtime. | Added overnight shift check to place shift end on the next calendar day in IST, and returned overtime minutes only when `>= 30`, else 0. |
| 5 | `create_employee` (lines 77-85) | Used check-then-insert (`find_one` then `insert_one`), creating race conditions under concurrent requests. | Sending parallel POST requests with the same `emp_code` created duplicate employee documents. | Created unique index on `emp_code` at startup and caught `DuplicateKeyError` to return 409 Conflict. |
| 6 | `create_employee` / `EmployeeIn` (lines 53-60) | Missing schema constraints: allowed identical `shift_start` and `shift_end`, omitted regex validation on `emp_code`, and lacked email validation. | POSTing `shift_start: "09:30"` and `shift_end: "09:30"` succeeded with 201 instead of 422. | Added strict Pydantic model with regex `^EMP\d{4,6}$`, email validator, and model validator ensuring `shift_start != shift_end`. |
| 7 | `list_employees` (line 93) | Incorrect pagination skip formula: `skip = page * page_size`. For page 1, skipped 20 items and dropped the entire first page. | Querying `GET /employees?page=1` returned results starting at index 20. | Fixed formula to `skip = (page - 1) * page_size`. |
| 8 | `list_employees` (line 94) | Total count ignored query filter: `total = db.employees.count_documents({})`. | Querying `GET /employees?department=Sales` returned total count of all employees in database. | Passed filter `q` to `count_documents(q)`. |
| 9 | `list_employees` (line 95) | Missing sort order; results returned in arbitrary database storage order. | Response order fluctuated across queries instead of deterministic `emp_code` ascending. | Added `.sort([("emp_code", ASCENDING)])`. |
| 10 | `punch_in` (lines 101-105) | Check-then-insert race condition allowed duplicate punches for the same employee and date. | Sending concurrent punch-in requests yielded multiple 201 responses. | Enforced compound unique index on `(emp_code, date)` and caught `DuplicateKeyError` returning 409. |
| 11 | `punch_in` (lines 102-103) | Attendance date calculation did not handle IST timezone or overnight shifts (R1). | A night shift worker (22:00-06:00) punching in at 01:00 IST was assigned the new day rather than the shift's starting date. | Localized instant to IST and checked if time is earlier than `shift_end` for overnight shifts to assign the previous calendar day. |
| 12 | `punch_in` (lines 102) | Did not truncate instants to whole seconds (R1). | Punch times stored millisecond fractions, altering downstream duration comparisons. | Truncated epoch milliseconds via integer floor division (`ms // 1000`) before storing and calculating. |
| 13 | `punch_in` (lines 118-120) | Injected `"id": str(res.inserted_id)` into response, leaking internal MongoDB IDs and violating OpenAPI contract. | Response schema validation failed on unexpected `id` property. | Removed `id` injection and serialized document strictly according to `AttendanceRecord`. |
| 14 | `list_attendance` (lines 144-147) | Loaded entire collection into memory (`list(find())`) and sorted with Python `docs.sort()`. Unscalable at 100k docs. | High memory consumption and severe latency when query executed on large collection. | Executed sorting and pagination directly inside MongoDB using `.sort([("date", DESCENDING), ("emp_code", ASCENDING)]).skip(skip).limit(page_size)`. |
| 15 | `list_attendance` (lines 136-143) | Did not validate `date_from > date_to`. | Querying `date_from=2026-07-20&date_to=2026-07-10` returned 200 with empty list instead of 422. | Added validation raising HTTP 422 Unprocessable Entity when `date_from > date_to`. |
| 16 | Global startup | Missing database indexes at startup. All queries executed slow full-collection scans (`COLLSCAN`). | MongoDB explain showed `COLLSCAN` across all collections. | Added automated idempotent index initialization in FastAPI `lifespan` handler. |

## What was examined and decided was NOT a defect
1. **`python-dotenv` loading priority:** Examined `load_dotenv()` at line 20. In Python, `load_dotenv()` by default does not override already set system environment variables (`override=False`). Therefore, externally injected `MONGO_URI` and `MONGO_DB` take precedence as required.
2. **Standard UTC+05:30 IST definition:** Examined `timezone(timedelta(hours=5, minutes=30))`. This is standard Python standard library without external dependencies, and accurately captures IST without daylight saving transitions.
3. **Natural key identification:** Examined addressing attendance records by `(emp_code, date)` rather than an internal ID. This correctly aligns with the domain model specified in `DATA_MODEL.md`.
